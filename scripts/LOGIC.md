# 施設空きチェックのロジック（処理の流れ）

## 全体の流れ

1. **設定を読む**（.env）
2. **予約サイトにアクセスし、サイトの画面の流れに沿って操作する**
3. **施設別空き状況（カレンダー表示）で ○/△/× を施設・日付ごとに取得する**
4. **前回と比べて空きが出た施設・日付だけ LINE に通知する**

※ 日付の配列（getTargetDates）は現在のフローでは使っていません。  
　「表示期間1ヶ月」＋「次の期間へ」を2回クリックすることで **計3ヶ月分** をチェックします。

---

## ステップ1: 設定を読む

- **scripts/.env**（またはプロジェクトルートの .env / .env.local）を読む。
- 使う値の例:
  - 予約サイト: `RESERVATION_USER_ID`, `RESERVATION_PASSWORD`
  - LINE: `LINE_CHANNEL_ID`, `LINE_CHANNEL_SECRET`, `LINE_USER_ID`（または `LINE_CHANNEL_ACCESS_TOKEN`）
  - 施設: `FACILITY_NAME` または `FACILITY_NAMES`（カンマ区切りで複数）
  - 時間帯表示: `TIME_SLOT_LABEL`（例: 夜間枠）、`TIME_SLOT_FILTER`（例: 夜間）
  - 利用目的: `PURPOSE_LABEL`（例: バドミントン）

---

## ステップ2: 予約サイトでの操作（1回のチェックで一連の流れ）

**対象URL:** 福岡市公共施設案内・予約システムのトップ  
`https://www3.11489.jp/fukuoka/user/Home`

### 2-1. トップを開く → ログイン

- 上記URLにアクセスする。
- 「ログイン」リンクがあればクリックし、.env の `RESERVATION_USER_ID` と `RESERVATION_PASSWORD` でログインする。

### 2-2. 空き照会へ進む

- 「空き照会」「申込」のリンクをクリック。なければ「Vacancy」「空き」を含むリンクをクリック。

### 2-3. 利用目的から探す

- **「利用目的から探す」** をクリック。
- **「屋内スポーツ」** をクリック。
- **「バドミントン」**（または `PURPOSE_LABEL`）をクリック。
- **「検索」** をクリック。

### 2-4. 施設選択画面

- 表示されている施設の中から、.env で指定した **施設名**（`FACILITY_NAME` / `FACILITY_NAMES`）に一致するものを **すべて選択** する。
- 画面上に指定施設がまだ出ていない場合は **「さらに読み込む」** をクリックして追加表示し、指定施設がすべて選べるまで繰り返す（最大30回まで）。
- 指定した施設のうち、最後まで見つからなかったものは **「対象施設が見つかりませんでした」** とログに出す。
- 選択が終わったら **「次へ進む」** をクリック。

### 2-5. 施設別空き状況（表示期間・条件・表示）

- **「表示期間を1ヶ月」**（または「1ヶ月」）をクリック。
- **「その他の条件で絞り込む」** をクリック。
- **「カレンダー表示」** を選択。
- 指定した時間帯（例: **夜間**＝`TIME_SLOT_FILTER`）を選択。
- **「表示」** をクリック。

### 2-6. ○/△/× の取得（1期間目）

- 表示されたページの **body テキスト** を取得する。
- 施設名ごとに、その施設名から次の施設名（または末尾）までのブロックを切り出す。
- 各ブロック内で:
  - **○** があれば「空きあり（○）」、なければ **△** があれば「空きあり（△）」、それ以外は「空きなし（×）」と判定。
  - 日付は「数字＋○/△/×」の並びから日（1〜31）を抽出し、表示中の月と組み合わせて `YYYY-MM-DD` にする。
- 各「施設・日付・○/△/×」について:
  - 状態キー（例: `南体育館_2026-03-15_夜間枠`）で `availability-state.json` の前回結果と比較。
  - **前回は空きありでなかった** かつ **今回 ○ または △** のときだけ LINE に通知する。
  - 通知文の例:  
    `【空き通知】南体育館の三月十五日(木)の夜間枠に空きが出ました。`  
    `予約はこちら：https://www3.11489.jp/fukuoka/user/Home`

### 2-7. 次の期間へ（2回繰り返し＝計3ヶ月分）

- **「次の期間へ」** をクリック。
- 再度 **「その他の条件で絞り込む」→「カレンダー表示」→ 時間帯選択 →「表示」** を行う（2-5 と同様）。
- 2-6 と同様に ○/△/× をパースし、施設・日付ごとに状態を保存し、空きが出た場合だけ LINE に通知する。
- もう一度 **「次の期間へ」** をクリックし、同じ手順で3期間目を取得・判定・通知する。

以上で **合計3ヶ月分**（1期間目・2期間目・3期間目）の空き状況をチェックし終える。

---

## ステップ3: 状態の保存

- 各「施設_日付_時間帯」の結果（空きあり / 空きなし）を `availability-state.json` に保存する。
- 次回実行時に「前回は空きなし → 今回空きあり」になった組み合わせだけ LINE に通知する。

---

## まとめ（ログインして、どこを見て〜）

1. **ログイン**  
   トップで「ログイン」があればクリックし、.env の利用者ID・パスワードでログインする。

2. **どこを見るか**  
   「空き照会」→「利用目的から探す」→「屋内スポーツ」→「バドミントン」→「検索」と進み、  
   **施設選択画面**で指定施設を選び（「さらに読み込む」で必要なだけ読み込み）、「次へ進む」をクリック。  
   続いて **施設別空き状況** で「表示期間1ヶ月」→「その他の条件で絞り込む」→「カレンダー表示」と指定時間帯（例: 夜間）を選んで「表示」し、  
   **「次の期間へ」を2回** クリックして、計 **3ヶ月分** のカレンダー表示を見る。

3. **何で「空き」と判断するか**  
   各期間の表示テキストで、施設名のブロック内に **○** または **△** があれば「空きあり」、それ以外は「空きなし（×）」とする。  
   日付は、数字と ○/△/× の並びから日を抜き出し、表示中の年・月と組み合わせて「施設・日付・時間帯」ごとに判定する。

4. **いつ LINE を送るか**  
   前回は空きありではなかったのに、今回「その施設のその日・時間帯は ○ または △」になったときだけ、  
   **「【空き通知】〇〇体育館の○月○日(○)の夜間枠に空きが出ました。予約はこちら：…」** という形で LINE に送る。

5. **期間**  
   サイトの「表示期間1ヶ月」＋「次の期間へ」2回で、**実行時点から見て 1ヶ月目・2ヶ月目・3ヶ月目** の3ヶ月分をチェックする。  
   （.env の CHECK_DATE / CHECK_DATE_END は現在のフローでは未使用。）

以上が、現在のスクリプトの「ログインして、どこを見て、何を根拠に空きと判断し、いつ・どんな文で LINE を送るか」のロジックです。
